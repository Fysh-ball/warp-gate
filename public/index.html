    Five things worth knowing first

    Your messages and files are encrypted here, in this browser what the server can and cannot see

    Everything is encrypted before it leaves your device. The server relays an encrypted handshake and then steps out of the way entirely. It never receives the keys, the file contents, the messages, or even the file names.

    The secret that unlocks the gate lives after the # in the link, which browsers never send to a server.

    Anyone with the link can join treat it like a password

    There are no accounts and no identity checks. The link is the only credential. Send it the way you would send a password, and only to the person you mean to.

    A gate holds a small group of devices. Once it is full, any further device is refused.

    Everyone in a gate sees everyone else's IP address Warp Gate is confidential, not anonymous

    Warp Gate connects your devices directly to each other. That is what keeps the server out of the data path, but it means every device in a gate learns the network address of every other device in it.

    This applies even if you loaded this page through a proxy. If hiding your network address matters, use a VPN or Tor that you trust.

    What this does not protect you from the honest limits
    • A compromised device, browser or extension on either end.
    • Screenshots, or a recipient who saves and forwards what you sent.
    • Anyone you choose to give the link to.
    • Traffic analysis: sizes and timings are visible to the network.

    For something extremely sensitive, encrypt it yourself before sending it as well. Full detail is in the Privacy Policy.

    Who is serving you this page worth knowing

    The only instance the authors run is https://warpgate.fysh.site. The source is public so anyone may host their own copy, which is encouraged, but an instance run by somebody else inherits none of the authors' trust.

    Whoever serves this page controls the code that does the encryption. That is true of every website that encrypts in the browser. A hostile operator could serve a modified page and nothing here would reveal it. If you need certainty, host it yourself from source you have read: there are no dependencies and no build step, so the files served are the files in the repository. Full detail in the FAQ.

    How it works

    Three steps, and the server sees none of it.

    The server introduces the browsers to each other and then gets out of the way. Your files never touch it.

    Open a gate

    You get a code and a QR. The secret in it is generated in your browser and is never sent to the server.

    The other device joins

    Scan or paste. Each pair of browsers agrees a key directly with each other, and adds a room password if you set one.

    Burn it

    Keys, messages and the room are gone. What is left is whatever the two of you chose to save.

    Paying for it

    No ads. Not one script that is not ours.

    An ad network needs its JavaScript on the page. On a page that holds your decryption key, that script could read it, and no promise in a privacy policy changes what code is able to do. So the money comes from somewhere else.

    What we charge for
    • A licence for closed products. Warp Gate is AGPL. If a company wants it inside something they do not publish the source of, they buy an exception.
    • Running it for you. Your own gate on your own domain, kept patched, for teams who want one and do not want to operate it.
    • Relay, when a direct link is impossible. Some corporate and mobile networks refuse to let two devices meet. Bandwidth through us costs real money, so that part is paid.
    What stays free, permanently
    • Every feature that exists today, with no limit added later
    • No cap on gate size, file size, or how many you open
    • No account, ever, including for the paid tiers' free users
    • No third-party script, tracker, pixel or analytics anywhere on the site

    Candidates

    What is missing, and what would be nice.

    Marked by whether it is a real gap in what the product already claims, or an addition worth considering.

    Shipped

    More than two people

    A gate is a small full mesh now. Every pair runs its own connection and its own keys, so nobody relays anybody else's traffic. Capped deliberately: the number of connections grows with the square of the group.

    Real gap

    Survive a phone reload on a password gate

    The key schedule takes a password, but the reload path does not carry it, so a refresh drops you out.

    Real gap

    Resume a big transfer

    A dropped connection restarts the file. Chunk-level resume is the difference between usable and not on mobile data.

    Nice to have

    Install it, and share into it

    A PWA with a share target: hold a photo in the gallery, share to Warp Gate, gate opens with it already attached.

    Nice to have

    Scan a code with the camera

    Today the phone shows the QR and the laptop reads it. The reverse direction needs the camera.

    Nice to have

    Already true

    Works when both of you are behind the same router

    Nice to have

    Run your own

    One container, no build step, no dependencies. The trust question is who serves the page, so self-hosting is the honest answer to it.

    The pledge

    Free forever, and that's a promise.

    Every feature that exists today stays free, permanently. Nothing that works now will later need a subscription. We charge companies for commercial use and for the things that cost us bandwidth, and if that ever stops covering the bill, the site gets smaller before it gets paywalled.
    How this worksin one paragraph

    Creating a gate generates a secret in your browser and puts it in the link, where the server never sees it. The other device derives the same keys from that link, both sides prove to each other that they hold it, and then your devices talk directly. Closing the gate destroys the keys and the room.

    • Put both devices on the same network, which almost always works.
