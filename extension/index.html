WARP GATE

Extension

What this extension is for

Warp Gate encrypts everything between two browsers and the server never holds a key. The weak point was never the encryption: it was how the code that does the encryption reaches you. On the website, the server, and anything able to terminate TLS in front of it, hands your browser a fresh copy of that code on every visit, and could hand a different copy to one targeted person. This extension carries the code instead. It is installed once, and it changes only when the browser applies a signed update from the store.

What installing this fixes

  • Per-request code substitution. The network cannot swap the client out from under you, because the client no longer travels over the network. Nothing on the gate page is fetched: not a script, not a stylesheet, not a font, not an icon.
  • Injection by whatever sits in front of the server. This is not hypothetical. Measured on 10 August 2026, the gate document served from the official instance came back 938 bytes larger than the file in the repository, because the CDN in front of it appends its own bot-detection script. That injection is harmless and the site's Content-Security-Policy stopped it running. It is still a party between the source and the browser modifying the page that holds a decryption key, and no header fixes the case where the same party serves a modified script file instead. There is nothing for it to modify here.

What installing this does not fix

This list is not a disclaimer. It is the part people get wrong.

  • The signalling server still sees the metadata. Your address, the timing, the room id, the sizes of requests, how long a gate lasted, and your per-seat token. Everything it carries is ciphertext and it holds no key, but a server that learns nothing about content still learns that you were there. Installing an extension changes none of that.
  • The other end. A gate link opens the ordinary web client on whoever you send it to, unless they have installed this too. Their delivery risk is unchanged until they do. The encryption between you is unaffected either way.
  • Your device and your browser. Malware, a compromised profile, or another extension with more privilege than this one sees everything. So does anyone looking at the screen.
  • The other participants. Anyone holding the link is a legitimate participant and can keep, screenshot or forward anything you send. Nothing prevents this and Warp Gate does not pretend to.
  • The store. The signed update channel is the trust root now. It is a narrower and far more accountable one than a per-request TLS terminator, because an update is the same bytes for everyone and it is reviewed, but it is not nothing.

The full accounting is in THREAT-MODEL.md in the repository, and the short version is in the FAQ.

Which server this signals to

Two browsers cannot find each other without something in the middle to pass the first few messages, so this extension still talks to a Warp Gate server. That server is not trusted in this design, which is exactly why the address is yours to choose: point it at your own instance and the trust question has a definite answer.

Scheme and host, nothing else. For example https://warpgate.fysh.site. Plain http is refused unless the host is localhost or 127.0.0.1, because an unencrypted signalling hop on a real network gives away everything the metadata list above describes to anyone on the path.

Changing this needs your permission to reach the new host, and the browser will ask for it. That prompt is not a formality: an extension that could already reach any host would be able to send your signalling somewhere you never chose, and this one deliberately cannot until you say so.

Checking this yourself

There is no build step and no dependency anywhere in this project, so the files inside this package are the files in the repository. The client here is a copy of the one in public/ with the network destination made explicit, because the web client addresses the server it was served by and this one has to be told. Every changed line carries an EXTENSION PATCH comment and the complete list is in extension/README.md.
